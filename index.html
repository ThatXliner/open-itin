Open Itinerary

An open, token-efficient JSON format for travel plans — designed for AI agents to output and apps to consume.

GitHub Try the validator

What it is

The format is a JSON Schema. A single file. Validate with any JSON Schema validator in any language. No library, no SDK, no lock-in.

Files use the extension .oitinerary.json and the MIME type application/vnd.open-itinerary+json.

It's to travel plans what iCalendar is to events — boring, useful, and open.

Design highlights

🎯

Every stop has a goal

Not just where you're going, but why. “Scenic viewpoint — stretch and take photos.” Forces AI agents to be explicit about intent.

📍

Coords are a cache, not truth

AI agents hallucinate lat/lng. The name (and addr) is authoritative. Coordinates are added by a geocoder post-generation.

⚡

Token-efficient by design

tz not timezone. dur not durationMinutes. cat not category. Save 25–35% output tokens vs verbose JSON.

📄

Flat catalogs, not deep nesting

Stops and routes are top-level, referenced by id from each day. No duplication when a stop appears in multiple days.

🔁

Alternatives are first-class

Stop-level alts for “instead of this restaurant, try that one.” Day-level flex for “choose N of these options.”

⏱

Duration ranges, not fixed times

dur: {min: 1.5, max: 2.5} acknowledges that travel is uncertain. Fixed times only when they matter (flights, reservations).

Example

Quick start

Validate any itinerary against the schema:

pip install jsonschema copy
python -c "import json, jsonschema; schema = json.load(open('open-itin.schema.json')); data = json.load(open('your-trip.json')); jsonschema.validate(data, schema); print('Valid')" copy

Then geocode it (adds real coordinates from OpenStreetMap):

python geocode.py your-trip.json copy
